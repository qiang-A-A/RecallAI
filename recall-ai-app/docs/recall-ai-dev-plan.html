里程碑与任务分解

8 WEEKS · 3 MILESTONES
W1-3
第 1-3 周

M1 · 录入闭环 P0FR-1/2/3

  • 工程脚手架:Vite + Vue3 + TS + Tailwind + FastAPI 目录
  • 四通道录入:文本 / 拍照 / 截图 / 对话
  • OCR 服务接入(PaddleOCR-VL HTTP 封装 + 降级)
  • AI 自动归档:学科 / 知识点 / 错因识别 + 回填
  • 错题列表:分类 / 筛选 / 搜索 / 分页 / 详情弹窗

  • Design System 落地:token 变量 / 基础组件(Button/Card/Badge)
验收:四通道均可成功入库;AI 识别回填可修正;OCR 不可用可手动补录;列表筛选/搜索/删除全可用;无 Key 时录入不中断
W4-6
第 4-6 周

M2 · 复习引擎与 AI 对话 P0FR-4/5/8

  • SM-2 间隔重复算法(纯函数 + ease_factor 管理)
  • 一键复习:到期清单 → 逐题作答 → 三档自评 → 提交
  • 3 级提示梯度(考点 → 思路 → 解析)AI 生成
  • 变式题生成:同考点不同面孔 + 四维质检重试
  • 复习计划:今日待复习 + 预计耗时 + 倦怠保护降频
  • AI 对话:流式回答 / 历史分组 / 新建对话 / 快捷提问
  • 对话内容「一键加入错题本」自动归档
  • 数据看板雏形:KPI + 环形图 + 柱状图(真实数据)
验收:SM-2 提交返回 next_review_at 与变式触发标记;连续 3 次失败触发专项入口;AI 对话首字 < 2s;历史/新建对话可交互
W7-8
第 7-8 周

M3 · 数据分析与发布 P1FR-6/7/9

  • 数据看板完整版:KPI / 环形占比 / 近十天柱状图 / 错因 TOP5 / AI 优化推荐

  • 导出:PDF(ReportLab 含中文字体)+ Markdown
  • 设置页:API Key 管理(保存/清除/测试连接)
  • 帮助中心:FAQ 手风琴 + 意见反馈
  • 空/加载/错误三态全面覆盖 + 响应式打磨
  • 200 题回归测试集 + API 集成测试(pytest)
  • 一键启动脚本 + README + 部署文档
验收:看板全部真实数据、下拉可交互;PDF/Markdown 导出中文正常;API Key 四态正确;全站零占位资源、三态齐全

05

开发规范

CONVENTIONS

5.1 前端规范

维度约定
样式Tailwind + CSS 变量(token);禁止硬编码颜色;紫=AI 蓝=用户 语义固定
组件通用 UI 走 ui/ 组件库(Button 5 变体/Card 3 种/Badge 7 变体);页面级组件放 views/
状态Pinia store 集中管理;列表页必实现 空/加载/错误 三态
数据API 统一走 api/client.ts 类型化封装;禁止组件内直接 fetch
交互按钮按压反馈、focus-visible 焦点环、Toast 全局反馈、动画只动 transform/opacity
响应式移动优先;≤640px 底部 Tab + 44px 触摸目标;表格 overflow-x:auto

5.2 后端规范

维度约定
分层api → services → repositories → models 单向依赖,禁止反向
降级AI/OCR/Vector 一律 try/except + is_available 守卫;失败返回降级结果不抛 500
校验入参 Pydantic v2 校验;AI JSON 输出必做解析重试(1 次)+ 兜底默认值
数据SQLAlchemy 2.0 类型注解;软删除 deleted_at;统一 DEMO_USER_ID(MVP 无登录)
API统一 /api/v1 前缀;错误返回 {detail};导出用 StreamingResponse/Response 带 Content-Disposition
密钥API Key 仅存服务端内存(运行时注入),不落盘、不返回明文、日志脱敏

5.3 工程规范

Git 提交
feat:/fix:/refactor:/docs:/test:/chore: 前缀;PR 需关联里程碑任务
代码质量
后端 py_compile + pytest 通过;前端 TS 严格模式、零 any 逃逸
环境
.env.example 维护;敏感值不提交;Vite 代理 /api → 8000
06

风险矩阵

RISK
高

AI 质量不达标

诊断知识点判错、变式题"换皮不换考点"、讲解幻觉 —— 直接打击"更懂学"的定位。
缓解:RAG 限定知识图谱 + 低置信度人工确认兜底 + 200 题回归集(采纳率 ≥85%);变式四维质检不合格自动重生成
中

OCR 服务不可用 / 依赖重

PaddleOCR-VL 需独立 GPU 服务,本地环境常不可达;安装重依赖易失败。
缓解:OCR 封装为 HTTP 可选依赖,import/运行失败优雅降级为手动录入;MVP 期不阻塞主链路
中

前端"演示壳"回归

按钮只弹 Toast 不接真实 API,用户感知"功能不可用"。
缓解:验收清单强制「无演示壳」;浏览器自动化实测(CDP)每里程碑跑一次全功能链路
中

性能不达标

万条错题下列表/复习接口 >500ms;AI 首字 >2s 体验差。
缓解:分页 + 索引;AI 流式 SSE;Weekly 报告加缓存;性能验收列入里程碑门禁
低

数据安全与合规

面向未成年人,API Key 泄露、隐私采集风险。
缓解:最小化采集 + 监护授权声明;Key 仅存内存不落盘;导出文件本地生成不缓存
低

成本失控

DeepSeek 调用量增长导致成本超预算。
缓解:每用户配额 + 轻量模型路由(诊断/讲解/变式分流);1 万 DAU 内月成本约 ¥2,900 为上限线

验收标准

ACCEPTANCE

7.1 功能验收(MVP 门禁)

四通道录入 文本/拍照/截图/对话均可成功入库;OCR 不可用降级可手动补录
AI 自动归档 配置 Key 后自动识别学科/知识点/错因并回填,可手动修正后确认
去重合并 录入相同题自动合并并累加错误次数
错题列表 筛选/搜索/分页/详情/编辑/删除全部可用,分类计数实时
一键复习 到期清单 → 三档自评 → SM-2 返回 next_review_at 与变式标记
数据看板 KPI/环形图/柱状图/错因/AI 推荐全部真实数据,下拉可交互
导出 PDF 下载成功且中文正常;Markdown 可导出
AI 对话 有 Key 正常流式回答;无 Key 明确降级提示;历史/新建可交互
设置 API Key 保存/清除/测试连接四态正确(未配置→400)
异常兜底 后端未启动页面不白屏,展示空态引导;全部按钮无演示壳

7.2 性能 / 质量验收

指标目标
API 响应(P95)< 500ms(1000 条错题下)
AI 流式首字< 2s
OCR 单图< 10s
首屏白屏< 2s(Lighthouse ≥ 80)
容量10,000+ 条错题
回归集200 题,AI 诊断采纳率 ≥ 85%
无占位资源unsplash/picsum/lorem 检查为 0
三态覆盖空/加载/错误 全页面齐全
可访问性WCAG AA(focus-visible / 对比度 / 44px 目标)
08

开发节奏建议

RHYTHM

8.1 双周迭代(每里程碑 2 个 Sprint)

Sprint 周期

2 周 / 迭代

周一规划 + 周二-四开发 + 周五联调自测;下周一演示评审

每日节奏

15 分钟站会

阻塞优先;AI/OCR 依赖问题当日上报,不拖入 Sprint 尾

里程碑评审

3 周一次

对照验收清单逐项过;浏览器自动化(CDP)全功能链路跑一遍

发布节奏

M3 后 v0.1

内测 → 修回归 → 公开;周活跃复习率作为上线后北极星跟踪

8.2 前后端协作建议

阶段并行工作
W1(搭台)前端:token/组件库/路由骨架;后端:模型/仓储/SM-2 纯函数 —— 双方先定 API 契约(第 04 章)
W2-3(录入)前端:四通道表单 + 识别卡片;后端:questions/ocr/analyze 三接口 —— 联调点:OCR 降级文案
W4-5(复习)前端:复习弹窗 + 三档自评;后端:SM-2 提交 + 变式触发 —— 联调点:next_review_at 展示
W6-7(对话+看板)前端:流式聊天 + 看板图表;后端:ai/chat + analytics/weekly —— 联调点:无 Key 降级体验
W8(打磨)双端:回归测试 + 响应式 + 三态 + 导出 + 设置页;产出部署文档

8.3 第一优先级(开工顺序)

① 后端 models + repositories + SM-2(无外部依赖,可先 TDD)→ ② 前端 token + 组件库 + 路由(设计系统落地)→ ③ questions 三接口 + 文本录入(打通最小闭环)→ ④ 逐通道扩展(拍照→对话)→ ⑤ 复习引擎 → ⑥ AI 对话 → ⑦ 看板/导出/设置 → ⑧ 打磨发布。
