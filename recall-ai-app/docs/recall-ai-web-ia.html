Recall AI Web 端信息架构

UX 产品经理视角的一级导航与页面层级设计 —— 层级控制在三级以内,贴合学生用户"少想、快达、有掌控感"的使用习惯。遵循 DESIGN.md v1.0 设计系统。

一级导航 5 项 + 全局入口 信息层级 ≤ 3 级 覆盖 9 大产品功能 配套 DESIGN.md v1.0
PART 01

设计前提:学生用户使用习惯

先立三条 UX 判断,后续所有结构决策都由它们推导。

习惯 1:高频动作要「一步可达」
  • 错题录入与一键复习是学生最高频动作,必须 全局可达(悬浮按钮),不能藏在某页里
  • 参照竞品教训:蜜蜂试卷"整理完就完了"、Anki"复习要靠自觉"——入口越浅,坚持率越高
习惯 2:认知负担要「三级封顶」
  • 学生心智被课程/作业占据,导航结构必须扁平:任何功能 ≤ 3 次点击可达
  • 层级拆解:一级导航(模块)→ 二级页面(列表/计划)→ 三级(详情/弹窗),杜绝第四级
习惯 3:状态要「看得见的掌控感」
  • 学生需要知道自己"错在哪、该复习什么、进步没有"——学习台与数据看板承担这个职能
  • 空状态不给惩罚感,给"下一步动作"引导(见 DESIGN.md Do's #4)
习惯 4:AI 是「同桌」不是「玄学」
  • AI 对话独立成一级导航(品牌差异化),但诊断结果必须可确认、可溯源(对应业务流程 U3 候选确认)
  • 紫色 = AI 能力、蓝色 = 用户操作,色彩语义贯穿(见 DESIGN.md §2)

PART 06

层级控制规则

三条硬性规则,确保信息架构不失控。

规则 1:三级封顶,绝不四层
  • 任何功能 ≤ 3 次点击可达(导航 → 模块页 → 详情/弹窗)
  • 三级之后的需求用弹窗/抽屉/行内展开承接,不建新页面
  • 反例禁止:错题详情 → 变式 → 解析 → 编辑笔记(四层)必须拆平
规则 2:高频全局化,低频靠边站
  • 录入、一键复习 = 全局悬浮,不占导航位
  • 导出 = 错题本/看板页内操作 + 设置中全量导出,不做独立导航
  • 帮助中心 = 低频,收进"设置与帮助"而非独立一级导航
规则 3:移动端折叠策略
  • 桌面侧栏 → 移动端底部 Tab(首页/错题本/复习/我的)
  • 数据看板、AI 助手在移动端降级为 Tab 内入口或二级
  • 三级页面(错题详情/变式)移动端用全屏页保持专注
规则 4:色彩语义贯穿层级
  • 蓝色入口 = 用户操作(录入/筛选)
  • 紫色入口 = AI 能力(诊断/对话/变式)
  • 绿色状态 = 系统反馈(掌握/完成/同步)
  • 导航高亮统一用品牌紫 + 薰衣草底(见 DESIGN.md §4.4)
